Hospital Information System Memory Simulation

SmartRAM is an interactive memory-management simulation that demonstrates how Operating System concepts can be applied to hospital information system workflows. Hospital software may need to access patient records, appointment schedules, laboratory information and pharmacy inventory repeatedly. These activities can be represented as memory-page requests handled under limited RAM capacity.

SmartRAM allows users to simulate these requests and observe how FIFO, LRU and Optimal page replacement algorithms decide which pages remain in memory and which pages are replaced. By examining page hits, page faults and memory utilization, users can understand how memory-management strategies influence application performance.

This is a simulation of operating system memory behavior, not a functioning hospital information system.

Hospital Workflow Simulations

Hospital software comprises multiple subsystems that access different types of information. SmartRAM represents each workflow as a series of memory-page requests processed under limited RAM capacity. Explore how page replacement algorithms handle each workload.

Patient Records Management

Patient records management involves accessing information such as patient registration details, demographic profiles, medical-history records and previous visit information.

SmartRAM represents repeated requests for different patient-related information as synthetic memory-page references. When a requested page is already in a simulated RAM frame, the request produces a page hit. When it is absent, the request produces a page fault.

FIFO, LRU and Optimal may retain different pages in memory, producing different page-fault counts for the same request sequence. Users can explore these differences in the simulation.

Operating Systems Theory

How Operating Systems Help Hospital Workflows Run Efficiently

The operating system manages limited RAM available to applications and determines which memory pages can remain in physical memory. Understanding memory-management concepts helps explain how page replacement algorithms affect application performance.

Memory Management

The operating system manages the limited RAM available to applications and determines which memory pages can remain in physical memory. When a requested page is already in memory, the application can access the required information without incurring a page fault.

Page Hits and Page Faults

When a requested page is already in memory, the request results in a page hit. When the requested page is not in memory, the request results in a page fault, which can introduce additional delay as the operating system arranges for the page to be brought into memory.

Page Replacement

When memory frames are full, a page replacement algorithm selects a page to remove so that another requested page can be loaded. FIFO, LRU and Optimal make replacement decisions differently, resulting in different page-fault counts for the same workload.

Performance Analysis

Comparing these algorithms helps explain how memory-access patterns and available memory capacity affect page faults and memory-management behavior. Reducing page faults can reduce memory-related delays, depending on the workload and system conditions.

Algorithm Benchmark

Page Replacement Algorithms Evaluated

SmartRAM implements the three standard OS page replacement algorithms for comprehensive academic comparison.

FIFO
First In, First Out

Replaces the page that entered physical memory earliest. Uses a FIFO queue structure. Low computational overhead, but can experience Bélády's Anomaly.

Complexity: O(1)
Space: O(n)
Zero tracking overhead Bélády's Anomaly
LRU
Least Recently Used

Replaces the page that has not been referenced for the longest duration. Closely models temporal locality common in interactive hospital user workflows.

Complexity: O(n)
Space: O(n)
High Hit Efficiency Stack Algorithm
OPTIMAL
Clairvoyant Benchmark

Replaces the page whose next use occurs farthest in the future. Provably optimal (lowest fault count), serving as the theoretical benchmark against all algorithms.

Complexity: O(n·f)
Space: O(n)
Minimum Faults Theoretical Only
